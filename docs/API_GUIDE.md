# 📘 دليل الربط البرمجي لستار موبايل (Star Mobile API v1.7)

مرحباً بك في بوابة المطورين الرسمية لستار موبايل. يتيح لك هذا الـ API الربط برمجياً مع خدماتنا لتنفيذ عمليات السداد والاستعلام من تطبيقاتك الخاصة بهيكلية احترافية وموحدة.

---

## 1. الإعدادات العامة (General Settings)

*   **الرابط الأساسي (Base URL):** `https://star26.vercel.app/api/external/v1`
*   **الإصدار الحالي:** `v1.7` (نسخة الحماية المالية)
*   **نظام الحماية (Authentication):** يجب إرسال مفتاح الربط في كل طلب داخل الـ Header.

### ● مثال لترويسة الطلب (Request Headers):
```http
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Accept: application/json
```

---

## 2. تسلسل العمل (Workflow)

يوضح المخطط التالي مسار الطلب من تطبيقك وحتى استلام الرد:

```text
العميل (تطبيقك)  ───►  نظام الحماية (Auth)  ───►  بوابة ستار موبايل (API)
                                                      │
    الرد الموحد (JSON)  ◄───  المزود (Provider)  ◄───┘
```

---

## 3. أكواد الحالة والأخطاء (Error Codes & HTTP Status)

| HTTP | Code | الوصف |
| :--- | :--- | :--- |
| 200 | `SM_SUCCESS` | تمت العملية بنجاح |
| 401 | `SM_UNAUTHORIZED` | مفتاح الربط غير صحيح أو مفقود |
| 403 | `SM_FORBIDDEN` | الحساب محظور أو لا يملك صلاحية API |
| 400 | `SM_VALIDATION_ERROR` | بيانات الطلب ناقصة (مثل نقص subscriberId) |
| 400 | `SM_INSUFFICIENT_BALANCE` | الرصيد غير كافٍ لتنفيذ العملية |
| 502 | `SM_PROVIDER_ERROR` | خطأ من مزود الخدمة الأساسي |
| 500 | `SM_INTERNAL_ERROR` | خطأ داخلي في النظام |

---

## 4. فحص الرصيد الشخصي (Get Balance)

*   **المسار:** `/balance` | **الطريقة:** `GET`
*   **الوصف:** يعيد رصيدك الحالي في محفظة ستار موبايل بالريال اليمني.

---

## 5. نظام الاستعلام الموحد (Unified Inquiry - GET /query)

| الخدمة | `service` | العمليات المتاحة (`action`) |
| :--- | :--- | :--- |
| **يمن موبايل** | `yem` | `query`, `solfa`, `queryoffer` |
| **YOU** | `you` | `query`, `queryoffer` |

| **ثابت / ADSL** | `post` | `query` |

## 6. نظام العمليات والسداد (Unified Payment - POST /pay)

*   **المسار:** `/pay`
*   **الوصف:** يستخدم لسداد خدمات الاتصالات والإنترنت. يتم خصم السعر الرسمي مباشرة.

---

## 7. منظومة الوادي المتطورة (Alwadi System v1.7)

تم تحديث نظام الوادي ليكون أكثر أماناً ودقة، حيث يتبع نظام "الخطوتين" الإلزامي لمنع الخسائر المالية.

### أ. الخطوة الأولى: الاستعلام (Lookup)
يجب الاستعلام عن الكرت أولاً للحصول على الاسم و `subscriberId`.

**● الطلب (Request):**
```json
// POST /alwadi
{
  "action": "lookup",
  "number": "رقم_الكرت"
}
```

**● الرد (Response):**
سيعيد النظام حقل `subscriberId` وهو **إلزامي** للخطوة التالية.

---

### ب. الخطوة الثانية: التجديد الفعلي (Renew)
يتم تنفيذ التجديد مع الخصم من الرصيد. **مستحيل تنفيذ الطلب بدون معرف المشترك.**

**● الأسعار المعتمدة للربط (خصم 2.5%):**
| الفئة | السعر الرسمي | سعر الربط (API) |
| :--- | :--- | :--- |
| شهرين (1) | 3,000 ر.ي | **2,925 ر.ي** |
| 4 أشهر (3) | 6,000 ر.ي | **5,850 ر.ي** |
| 6 أشهر (7) | 9,000 ر.ي | **8,775 ر.ي** |
| سنة (9) | 15,000 ر.ي | **14,625 ر.ي** |

**● الطلب (Request):**
```json
// POST /alwadi
{
  "action": "renew",
  "number": "رقم_الكرت",
  "packageId": "1", 
  "subscriberId": "المعرف_المستخرج_من_الاستعلام" 
}
```

---

### ج. وضع التجديد التجريبي (Test Renew)
يستخدم لتجربة الربط البرمجي والتأكد من الخصم والسجل دون تفعيل كرت حقيقي في المنظومة. سيتم خصم الرصيد وإعادته فوراً.

**● الطلب (Request):**
```json
{
  "action": "test_renew",
  "number": "رقم_الكرت",
  "packageId": "1",
  "subscriberId": "أي_رقم"
}
```

---

## 8. ملاحظات تقنية هامة

*   **الحماية المالية:** النظام يرفض أي طلب تجديد (`renew`) إذا كان الـ `subscriberId` مفقوداً.
*   **الخصم الآلي:** يتم خصم القيمة المخفضة (2.5% أقل) تلقائياً من رصيد حساب العميل المربوط بالمفتاح.
*   **Timeouts:** اضبط وقت الانتظار في تطبيقك على 60 ثانية.
*   **تنبيه:** يرجى عدم مشاركة مفتاح الـ API الخاص بك مع أي جهة غير موثوقة.
